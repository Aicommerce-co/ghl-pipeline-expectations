03"Quick information about each lead, including the country, on the card"

"The pipeline should display quick information about each lead, including the country, on the card." — GC Oct 28 · permalink ↗
Shipped: geo tags from phone prefix, displayed on every card.
GHL's native contact.country is junk — verified: 'AE' on +1 (US) numbers, 15k blank. So the sync worker stamps geo- tags from the phone prefix instead: 25,395 contacts geo-stamped of 34,577 scanned (geo-us, geo-uk, geo-br, geo-de, …) new contacts get stamped automatically by the 15-min worker.
Why tags and not the country field / custom fields: tags render on opportunity cards natively today; the country field data is unusable, and custom fields would need UI setup per card view. If Peter prefers a real "Country" column, that's a follow-up.

08Forensic notes — deliberately NOT inside GHL

No native GHL workflows — sync/move logic runs as API-side cron. Why: no workflow-UI access at build time; API logic is versioned and testable. Trade-off: if the cron box dies, sync pauses (logs tell you immediately).
No custom fields — country/status ride on tags. Why: tags already display on cards; contact.country is junk (verified 'AE' on +1 numbers). Trade-off: no columnar country reporting yet.
38 legacy cards from a pre-fix run were left in place (no-delete rule) — harmless, documented.
'Redeem page' stage unwired — redeem pages expose campaign-level sharedid only; needs Peter's per-lead link scheme.
Zero assignedTo beyond the first 60 — reps were added Oct 29; the 20-cards-each batch is the pilot. Scale-up is one command.
