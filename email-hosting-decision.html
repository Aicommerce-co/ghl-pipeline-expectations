The 4 realistic options

A · All Purelymail — recommended
B · Hybrid: G Suite ×1 + Purelymail
C · All Infomaniak (already paid)
D · Zoho Lite (suite feel)
A — everything on Purelymail. $10/yr total.
All domains (peterszabo.co, aicommerce.co, sourcehacker.com, virai.com, pszabo.com…) get MX → purelymail, per-domain DKIM, catch-alls per domain so no address ever bounces. Reps connect Apple Mail/Outlook/Thunderbird via IMAP or Purelymail's webmail; MFA + app passwords supported.

Lose: Gmail UI, Google Calendar sync, Gemini in Gmail. Mail history: Purelymail has a mail porting tool + Pedro's takeout.google.com export path (already suggested in the GC).
Keep: Drive/Docs/Calendar can stay as free Google accounts — only mail moves. Nothing else breaks: Stripe, GHL, Sendy all just send to addresses; MX change is invisible to senders.
Cost: $10/yr + zero per-seat. Risk: small provider (fair-use soft limits); storage metered loosely — fine for text mailboxes, heavy attachments users should archive.
B — Peter keeps one G Suite seat, everyone else Purelymail. $94/yr.
Peter's me@peterszabo.co stays Gmail (Stripe, history, UI he likes). Rep mailboxes (adil@, aislinn@, alokesh@, anthony@, ardita@, aron@…) move to Purelymail — same addresses, same domain; senders notice nothing.
Caveat: addresses on the same domain as Peter land on Purelymail while his lands on Google — that's exactly the "one domain → one MX" constraint, and it cannot work for a single domain split per-user. So B requires either: (i) reps keep @peterszabo.co and the WHOLE domain moves to Purelymail except Peter gets @pszabo.com or a Google Workspace secondary domain… not clean; or (ii) simpler: the whole peterszabo.co domain moves to Purelymail and Peter's mail is forwarded there — no true hybrid on one domain.
Honest verdict: the clean hybrid is per-DOMAIN, not per-user: e.g. peterszabo.co → Purelymail for everyone, and Peter personally uses pszabo.com on a single G Suite seat ($84/yr) if he insists on Gmail.
C — everything on Infomaniak. $0 incremental (already paid).
Service 1113470 already exists; Renato is live on it; we cut 3 domains to it on Nov 2 and it worked (DNS side perfect). Mailbox creation is manager-UI only (no public API for mailbox create) — manual clicking per mailbox, ~1 min each.
Today's lesson built in: the Renato bounce happened because MX pointed at Infomaniak before the me@ mailbox existed. Fix-then-cut: create ALL mailboxes in the UI first, flip MX last.
vs Purelymail: comparable price; Infomaniak has a webmail UI and apps, European deliverability, calendar; mailbox creation is manual UI (no API). Purelymail wins on automation (full API/portal control) and the porting tool.
D — Zoho Mail Lite, $12/user/yr.
The "real suite feel" budget option: webmail + mobile apps + calendar + 5GB/user, IMAP/POP, custom-domain DKIM. At 10 users = $120/yr — 12× Purelymail but 93% cheaper than G Suite.
Choose only if reps actually need app-like webmail + calendars bundled. Otherwise it's paying per-seat for something Purelymail gives free via IMAP clients.

Recommendation: Option A (all Purelymail) — or C if Pedro/Peter value Infomaniak's webmail and want zero new vendor. In both: create mailboxes FIRST, flip MX per domain SECOND, keep SPF merged with all legit senders, per-domain DKIM from the provider panel (never reuse keys across domains), and takeout.google.com export before any Google cutover. Keep DNS TTLs low (300s) for fast rollback. Every cutover is reversible in <2 min via the Cloudflare API (proven twice this week).

Migration plan (whichever option wins)

Phase 0 — Peter decides
  • Pick option (A/C recommended). Decide if ANYONE needs Gmail UI long-term → if yes, that person moves to his own domain seat (Option B pattern), never shared-domain per-user split.
  • Roster freeze: list every live mailbox + which domain (Peter's Nov 3 screenshot = seed list; Pedro has admin access to enumerate the rest).
Phase 1 — provision (before any DNS touch)
  • Create every mailbox + catch-all on the target provider; set temp passwords; rep changes password on first login.
  • Purelymail: import old mail via porting tool / takeout mbox import. Infomaniak: import from takeout too.
  • Record per-domain DKIM selectors; prep SPF merges (keep ClickFunnels/HelpScout/emsd1/ip4:62.83.18.84 includes).
Phase 2 — cut (per domain, 2 min each, reversible)
  • Cloudflare API: swap MX (delete old set, add provider's), merge SPF, publish DKIM/DMARC. Same recipe executed 3× on Nov 2 and re-executed for today's revert.
  • Verify live via dig @1.1.1.1 + real send/receive tests (today's Renato bounce = the proof that readback matters).
  • Order: lowest-stakes domain first (pszabo.com), peterszabo.co LAST (Stripe + reps live there), after hours.
Phase 3 — decommission G Suite
  • takeout.google.com full export (already suggested in GC) → keep as archive.
  • Cancel subscription only AFTER a week of clean send/receive + Stripe test. Google account logins (Drive/Analytics/GHL SSO if any) stay intact as free accounts.
